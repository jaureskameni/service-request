# Error Codes — Service Request

Business errors are returned with their stable code as the HTTP response message. The HTTP status
and code together identify the error; clients should use the code rather than the descriptive text.

| Type | HTTP | Code métier | Description |
|---|---:|---|---|
| `BadRequestException` | `400` | `SERVICE_REQUEST_400_001` | Pagination data is invalid: page must be non-negative and limit must be between 10 and 100. |
| `ForbiddenException` | `403` | `SERVICE_REQUEST_403_001` | The request does not belong to the current service provider. |
| `ForbiddenException` | `403` | `SERVICE_REQUEST_403_002` | The request does not belong to the current user. |
| `ForbiddenException` | `403` | `SERVICE_REQUEST_403_003` | The service provider is not approved (`APPROVED`). |
| `ResourceNotFoundException` | `404` | `SERVICE_REQUEST_404_001` | User not found. |
| `ResourceNotFoundException` | `404` | `SERVICE_REQUEST_404_002` | Service provider not found. |
| `ResourceNotFoundException` | `404` | `SERVICE_REQUEST_404_003` | Service request not found. |
| `ConflictException` | `409` | `SERVICE_REQUEST_409_001` | The transition is invalid for the current status. |

Codes are defined in `ServiceRequestErrorCode` and mapped to HTTP exceptions by
`DefaultDomainToHttpExceptionTranslator`. Errors generated by request binding/validation (such as an
invalid UUID, enum value, or malformed body) also return `400`, but do not carry a service business
code. Missing or invalid bearer tokens return `401` through Spring Security and likewise do not
carry a service business code.
